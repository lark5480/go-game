# 围棋 · Go Game

一个基于 React + TypeScript + Vite 的网页围棋对弈应用。支持人机对战与双人同屏，
内置零分配规则引擎与 Web Worker 中运行的 MCTS（蒙特卡洛树搜索）AI，
针对大棋盘做了系统性的性能优化。

## 功能特性

- **对局模式**：人机对战（执黑/执白可选，执白时 AI 自动开局）、双人同屏
- **棋盘规格**：9 路 / 13 路 / 19 路
- **AI 难度**：
  - 初级——启发式打分（中心偏好、提子、打吃/叫吃感知、边线惩罚），瞬时响应
  - 中级 MCTS——UCT 蒙特卡洛树搜索，在 Web Worker 中运行，不阻塞界面
  - 降级可见——Worker 不可用、启动失败、超时或异常时回退初级，并在界面明确提示，不再静默降级
- **棋谱（SGF）**：导入 `.sgf` 复盘（主分支、让子、两种 pass 写法；不支持的棋盘尺寸与矩形棋盘会明确拒绝并说明原因）、导出当前对局（含让子与结果）
- **完整规则引擎**：提子、禁自杀、全局禁同型（superko）、双 pass 终局
- **终局保障**：AI 与人类遵守同一套禁同型规则；一方停着后另一方回停即进入数子，
  AI 无合法着法时自动停着——对局必定能走到终局计算，不会无限续弈
- **中国规则数目法**：终局可点击标记死子、实时计子，贴目 7.5
- **对局操作**：Pass、悔棋（人机模式自动回退两手）、认输、直接终局计算，
  终局后可「再来一局」（完整保留上一局的模式/棋盘/难度配置）
- **体验细节**：Canvas 绘制的木质棋盘、落子/提子音效、最后一手高亮、悬停预览

## 快速开始

环境要求：Node.js ≥ 20.19，包管理器使用 pnpm。

```bash
pnpm install          # 安装依赖
pnpm dev              # 启动开发服务器
```

常用脚本：

| 命令 | 说明 |
| --- | --- |
| `pnpm dev` | 启动 Vite 开发服务器 |
| `pnpm build` | 类型检查（`tsc -b`）+ 生产构建，输出到 `dist/` |
| `pnpm preview` | 本地预览生产构建产物 |
| `pnpm test` | 以 watch 模式运行 Vitest |
| `pnpm exec vitest run` | 单次运行全部测试 |
| `pnpm lint` | ESLint 检查（0 警告门槛） |

## 架构要点

### 规则引擎：参考实现 + 快速路径双轨

- `engine/rules.ts` 的 `legalMoveResult` 是**语义参考实现**：整盘克隆后落子、提子、验气，
  清晰但开销大，用于对局主流程与测试基准。
- `engine/fast-rules.ts` 是**热路径专用**的等价实现：扁平 `Uint8Array` 棋盘 +
  预计算邻居表 + 代数戳（generation stamp）复用缓冲区，合法性探测零分配、
  试错只触碰几个格子并自动还原。
- `fast-rules.test.ts` 用种子随机局面逐空点断言两套实现完全一致
  （合法性、提子数、落子后己方气数、提交后的盘面），保证快速路径不会偏离规则语义。

### MCTS（中级 AI）

- 树节点持有扁平棋盘副本，选择/扩展/回传为标准 UCT；
  未扩展走着惰性生成，树深不受限。
- playout 维护"贴石空点"活候选表（半径 2 邻域，落子/提子时 O(1) 增量增删），
  随机试着不再全盘扫描；合法性探测找到第一口气即提前返回；
  **禁止单劫立即回提 + 步数硬上限**，杜绝无限提子循环导致的搜索永不返回。
- 根节点过滤会排除所有重现历史局面的走着（与对局 superko 一致），
  搜索在 Web Worker 中执行，以 600ms 墙钟时间为唯一预算（迭代上限仅作
  失控保险丝），主线程保持流畅；基准实测 19 路中盘约 360 次模拟 / 600ms。
- 客户端保护：Worker 构造失败（如 CSP 缺 worker-src）、加载出错、1.5s 超时
  都会立即回退到初级策略并终止该 Worker，下一次请求自动重建——
  任何一条失败路径都不会卡住对局。

### AI 回合调度（store）

- AI 落子前同样校验全局禁同型；候选层（初级打分、MCTS 根）先行过滤，
  调度层兜底复核，违规着法一律视为无着可下；AI 层抛出的任何异常
  （如 Worker 不可用）也按"无着可下"处理，绝不让界面卡死。
- **停着策略**：对方刚停一手时 AI 回停一手（直接进入数子阶段）；
  AI 自身无合法着法（含被禁同型封死）时也自动停着——两条路径保证
  "连续两停 → 终局计算"总能到达，游戏永远不会悬死在 AI 回合上。
- **aiThinking 生命周期**：`maybeRunAi` 全路径 try/finally 兜底清位，
  悔棋按钮在 AI 思考中禁用（store 与 UI 双重防护）——过期的搜索
  无论被悔棋、认输还是返回菜单打断，状态标志都不会残留。

### 渲染与状态

- Zustand 按切片订阅状态；棋盘为单个 `<canvas>`：
  木纹/网格/星位缓存在离屏画布（仅尺寸变化时重建），
  每帧只叠加棋子与标记，且所有黑/白棋子共享两个径向渐变。
- 音效全局共享一个 `AudioContext`，每手棋只触发一次，避免浏览器上下文数量上限。

## 围棋规则说明

- 采用**中国规则**：终局按"子数 + 地域"计算，白方贴 7.5 目。
- 落子后立即提走无气的对方棋组；禁止自杀；**全局禁同型**（position superko，
  以 Zobrist 哈希记录历史局面）——人类与 AI 双方同等约束，来回提子无法无限循环。

### 怎么才算赢？

胜负**不看提子数**。终局时分别计分：

```
黑得分 = 黑存活子数 + 黑地盘 + 提获白子
白得分 = 白存活子数 + 白地盘 + 提获黑子 + 7.5（贴目）
分高者胜。
```

提子只是过程战果：你提了 52 颗，但如果自己的地盘丢得更多，终局仍会输；
反过来吃得少、围得多也能赢。对局中侧栏的「形势粗估」就是按当前盘面
即时套用这套公式给出的参考值（未终局，仅供参考）。

想结束对局：点 **Pass**（AI 会回停并进入数子阶段），或直接点
「进入数子」/「直接终局计算」。数子阶段可点击棋盘标记死子，
确认后在结算弹窗查看双方"存子＋地＋提子＋贴目"的完整明细。

## 部署

项目是**纯静态前端**（AI 在浏览器 Web Worker 中运行，无后端），可托管到任意静态服务。

### EdgeOne Makers

根目录的 `edgeone.json` 已声明部署配置，导入仓库或 CLI 部署时自动生效：

| 项 | 值 |
| --- | --- |
| 安装命令 | `pnpm install` |
| 构建命令 | `pnpm build` |
| 输出目录 | `dist` |
| Node 版本 | `22.21.1` |

> Node 版本不可低于 20.19：Vite 7 有此要求，而 EdgeOne 预装的 `20.18.0`
> 会导致构建失败。若在项目设置里手改版本，请选 22.x 或 24.x。

两种方式：

1. **Git 部署（推荐）**：推送到 GitHub 后在控制台「导入 Git 仓库」，框架预设会
   自动识别为 Vite；对生产分支的每次提交自动触发重新部署。
2. **CLI 部署**：

   ```bash
   npm install -g edgeone
   edgeone login
   edgeone makers deploy -n go-game
   ```

### 其他静态托管

`pnpm build` 输出到 `dist/`，直接上传该目录即可。注意构建环境的 Node 需 ≥ 20.19。

## 开发说明

- 提交前请确保 `pnpm lint` 与 `pnpm exec vitest run` 通过；`main` / `dev` 分支的
  推送与 PR 会由 `.github/workflows/ci.yml` 自动执行同样的检查（含生产构建）。
- 修改规则相关代码时，务必同步维护 `fast-rules.test.ts` 的等价性断言——
  这是防止性能优化引入语义偏差的安全网。
- 修改 SGF 相关代码时，同步维护 `src/sgf/sgf.test.ts` 的兼容性断言
  （坐标 / pass / 压缩点列 / 矩形棋盘 / `CA` 字符集 / 往返无损）——
  这是防止棋谱读写引入兼容性退化的安全网。
