# 围棋 · Go Game

一个基于 React + TypeScript + Vite 的网页围棋对弈应用。支持人机对战与双人同屏，
内置零分配规则引擎与 Web Worker 中运行的 MCTS（蒙特卡洛树搜索）AI，
针对大棋盘做了系统性的性能优化。

## 功能特性

- **对局模式**：人机对战（执黑/执白可选，执白时 AI 自动开局）、双人同屏
- **棋盘规格**：9 路 / 13 路 / 19 路
- **AI 难度**：
  - 初级——启发式打分（中心偏好、提子、打吃/叫吃感知、边线惩罚），瞬时响应
  - 中级 MCTS——UCT 蒙特卡洛树搜索，在 Web Worker 中运行，不阻塞界面
- **完整规则引擎**：提子、禁自杀、全局禁同型（superko）、双 pass 终局
- **终局保障**：AI 与人类遵守同一套禁同型规则；一方停着后另一方回停即进入数子，
  AI 无合法着法时自动停着——对局必定能走到终局计算，不会无限续弈
- **中国规则数目法**：终局可点击标记死子、实时计子，贴目 7.5
- **对局操作**：Pass、悔棋（人机模式自动回退两手）、认输、直接终局计算
- **体验细节**：Canvas 绘制的木质棋盘、落子/提子音效、最后一手高亮、悬停预览

## 快速开始

环境要求：Node.js ≥ 20.19，包管理器使用 pnpm。

```bash
pnpm install          # 安装依赖
pnpm dev              # 启动开发服务器
```

常用脚本：

| 命令 | 说明 |
| --- | --- |
| `pnpm dev` | 启动 Vite 开发服务器 |
| `pnpm build` | 类型检查（`tsc -b`）+ 生产构建，输出到 `dist/` |
| `pnpm preview` | 本地预览生产构建产物 |
| `pnpm test` | 以 watch 模式运行 Vitest |
| `pnpm exec vitest run` | 单次运行全部测试 |
| `pnpm lint` | ESLint 检查（0 警告门槛） |

## 架构要点

### 规则引擎：参考实现 + 快速路径双轨

- `engine/rules.ts` 的 `legalMoveResult` 是**语义参考实现**：整盘克隆后落子、提子、验气，
  清晰但开销大，用于对局主流程与测试基准。
- `engine/fast-rules.ts` 是**热路径专用**的等价实现：扁平 `Uint8Array` 棋盘 +
  预计算邻居表 + 代数戳（generation stamp）复用缓冲区，合法性探测零分配、
  试错只触碰几个格子并自动还原。
- `fast-rules.test.ts` 用种子随机局面逐空点断言两套实现完全一致
  （合法性、提子数、落子后己方气数、提交后的盘面），保证快速路径不会偏离规则语义。

### MCTS（中级 AI）

- 树节点持有扁平棋盘副本，选择/扩展/回传为标准 UCT；
  未扩展走着惰性生成，树深不受限。
- playout 维护"贴石空点"增量列表（半径 2 邻域），随机试着不再全盘扫描；
  **禁止单劫立即回提 + 步数硬上限**，杜绝无限提子循环导致的搜索永不返回。
- 根节点过滤会排除所有重现历史局面的走着（与对局 superko 一致），
  搜索在 Web Worker 中执行（预算 600ms / 至多 900 次迭代），主线程保持流畅；
  客户端超时保护为 1.5s，超时才回退到初级策略。

### AI 回合调度（store）

- AI 落子前同样校验全局禁同型；候选层（初级打分、MCTS 根）先行过滤，
  调度层兜底复核，违规着法一律视为无着可下。
- **停着策略**：对方刚停一手时 AI 回停一手（直接进入数子阶段）；
  AI 自身无合法着法（含被禁同型封死）时也自动停着——两条路径保证
  "连续两停 → 终局计算"总能到达，游戏永远不会悬死在 AI 回合上。

### 渲染与状态

- Zustand 按切片订阅状态；棋盘为单个 `<canvas>`：
  木纹/网格/星位缓存在离屏画布（仅尺寸变化时重建），
  每帧只叠加棋子与标记，且所有黑/白棋子共享两个径向渐变。
- 音效全局共享一个 `AudioContext`，每手棋只触发一次，避免浏览器上下文数量上限。

## 围棋规则说明

- 采用**中国规则**：终局按"子数 + 地域"计算，白方贴 7.5 目。
- 落子后立即提走无气的对方棋组；禁止自杀；**全局禁同型**（position superko，
  以 Zobrist 哈希记录历史局面）——人类与 AI 双方同等约束，来回提子无法无限循环。

### 怎么才算赢？

胜负**不看提子数**。终局时分别计分：

```
黑得分 = 黑存活子数 + 黑地盘 + 提获白子
白得分 = 白存活子数 + 白地盘 + 提获黑子 + 7.5（贴目）
分高者胜。
```

提子只是过程战果：你提了 52 颗，但如果自己的地盘丢得更多，终局仍会输；
反过来吃得少、围得多也能赢。对局中侧栏的「形势粗估」就是按当前盘面
即时套用这套公式给出的参考值（未终局，仅供参考）。

想结束对局：点 **Pass**（AI 会回停并进入数子阶段），或直接点
「进入数子」/「直接终局计算」。数子阶段可点击棋盘标记死子，
确认后在结算弹窗查看双方"存子＋地＋提子＋贴目"的完整明细。
